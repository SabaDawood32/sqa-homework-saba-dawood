# Assertions — "What is Permission?"

The response can be different on every run, so I didn't make the tests depend on exact wording.

All the checks are handled inside `ResponseAssertions.assertValidAgentResponse()`. This is called by `pillClickProducesResponse`, `freeTextProducesResponse`, and `consecutiveMessagesPreserveHistory`. The LLM evaluation rubric is defined in `evals/promptfooconfig.yaml`.

## What I Check

* **Response is not blank:** An empty response should never pass the test.
* **Reasonable response length:** The response must be between 100 and 2000 characters. This is just a sanity check — anything below 100 could indicate a dead/incomplete response, while more than 2000 could indicate runaway generation.
* **Relevant content:** The response needs to contain at least 3 of these 6 topic keyword stems: `data`, `earn`, `shar`, `agent`, `wallet`, `opportunit`. I use stems so words like "sharing" can match `shar`. I chose 3 out of 6 so the check isn't too loose but also doesn't reject a shorter answer that is still correct.
* **No obvious failure messages:** I check for 8 failure markers such as `undefined`, `error:`, `traceback`, and `"as an ai language model"`. A polite refusal is also treated as a failed response because the application didn't answer the user's question.
* **Not an echo:** The response shouldn't simply repeat the user's question.
* **Stream completed:** `waitForAnswer()` waits for the response to stop changing across 3 consecutive reads. It also ignores temporary `"is typing…"` placeholders and throws after 30 seconds if the response never settles. This is reported as a stuck stream rather than an invalid answer.

## What I Don't Check

I intentionally don't check exact wording, exact response length, markdown formatting, specific numbers, or response time. The 30-second limit is only a timeout to catch a stuck response, not a performance SLA.

## Why I Added an LLM Judge

Keyword checks alone aren't enough. For example, a response about a browser permission dialog could still contain words like "data", "agent", and "sharing" and incorrectly pass.

The LLM judge checks the actual meaning of the response — specifically whether it explains that users can earn from sharing their own data, mentions an AI agent or a wallet, and doesn't suggest that their data is sold without consent. It is a simple pass/fail evaluation and doesn't depend on a fixed reference answer that could become outdated.

One important detail is that the judge evaluates the **actual response generated by the application**. The test saves the live response to a file, and the judge reads that response back. It does not generate a new answer through a re-prompt.

Finally, if the LLM judge itself fails to run, I report that separately from the application response being rejected. This prevents a problem with the grader from being incorrectly reported as a product test failure.
